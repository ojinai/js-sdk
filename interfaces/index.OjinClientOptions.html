    OptionalinitialConnectDelayMs

    initialConnectDelayMs?: number

    Fixed delay in milliseconds between initial-connect retry attempts.

    There is intentionally no exponential growth here — a constant short delay surfaces misconfiguration quickly rather than hiding it behind growing wait times. Distinct from reconnectBackoff.initialMs, which seeds the exponential-backoff curve used for live-drop reconnection.

    Default: 500.

    OptionalmaxRequestsPerSecond

    maxRequestsPerSecond?: number

    Maximum number of outbound messages per rolling 1-second window.

    The flashhead-lite server enforces 6 req/sec per connection; this option applies client-side throttling to avoid tripping RATE_LIMITED in normal operation. Excess calls are buffered in the outgoing queue rather than rejected.

    OptionaloutgoingQueue

    outgoingQueue?: {
        maxMessages?: number;
        onOverflow?: "reject" | "dropOldest" | "dropNewest";
    }

    Configuration for the pre-ready outgoing message buffer. Only relevant when autoWaitForReady is true.

    Type Declaration

    • OptionalmaxMessages?: number

      Maximum number of messages to buffer while waiting for the inference server to become ready. When the limit is reached, onOverflow determines what happens. Default: 100.

    • OptionalonOverflow?: "reject" | "dropOldest" | "dropNewest"

      Behaviour when maxMessages is reached:

      • 'reject' (default) — rejects the sendMessage call immediately with QueueFullError carrying details.queueDepth and details.maxMessages.
      • 'dropOldest' — removes the oldest buffered message (its sendMessage Promise rejects with QueueFullError) and enqueues the new message in its place. Emits OjinEvent.QueueOverflow with { dropped: N }, rate-limited to one emission per 5-second window.
      • 'dropNewest' — silently discards the new message; the sendMessage Promise resolves immediately as a no-op. Emits OjinEvent.QueueOverflow with { dropped: N }, rate-limited to one emission per 5-second window.
